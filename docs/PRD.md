# AI Quant Lab — PRD (Product Requirements Document)

> **버전:** v0.1 (초안)
> **작성일:** 2026-08-04
> **상태:** 논의 중 (Draft)

---

## 1. 개요 (Overview)

**AI Quant Lab**은 국내 주식(KRX)을 대상으로, LLM과 머신러닝을 활용해 퀀트 투자 전략을
**생성 → 백테스트 → 성과 분석**하는 개인용 연구 실험실이다.

전략 아이디어를 자연어로 던지면 LLM이 실행 가능한 전략 코드로 변환하고, ML 예측 모델이
시그널을 보조하며, 백테스트 엔진이 과거 데이터로 성과를 검증한 뒤 리포트로 정리한다.

초기에는 **본인 연구용 도구**로 출발하지만, 추후 **외부 사용자 대상 제품화**가 가능하도록
모듈을 느슨하게 결합(loose coupling)하고 각 계층을 교체 가능하게 설계한다.

---

## 2. 목표 / 비목표

### 2.1 목표 (Goals)
- 자연어 전략 아이디어 → 실행 가능한 전략으로 변환 (LLM)
- ML 모델로 수익률/방향성 예측 시그널 생성
- 재현 가능하고 신뢰할 수 있는 백테스트 (look-ahead bias, 수수료/슬리피지 반영)
- 표준화된 성과 리포트 (수익률, MDD, Sharpe 등)
- CLI 한 줄로 실험을 반복 실행하고 결과를 파일로 축적

### 2.2 비목표 (Non-Goals, MVP 기준)
- 실시간 시세 연동 / 실거래 자동매매 → **범위 밖 (추후 단계)**
- 페이퍼 트레이딩 → 범위 밖 (추후)
- 웹 대시보드 UI → 범위 밖 (CLI + 리포트 파일로 시작)
- 해외 주식 / 암호화폐 / 파생 → 범위 밖 (KRX 우선)
- 멀티유저 / 인증 / 과금 → 범위 밖 (제품화 단계에서)

## 3. 사용자 & 시나리오

### 3.1 페르소나
- **1차 사용자 (지금):** 전략을 직접 연구하는 개인 (= 나). 파이썬/CLI에 익숙.
- **2차 사용자 (추후):** 코드를 깊게 모르지만 전략을 실험하고 싶은 트레이더.

### 3.2 핵심 사용자 시나리오
1. **아이디어 → 전략:** "20일 이평선 골든크로스 + 거래량 급증 종목 매수" 를 자연어로 입력하면
   LLM이 전략 로직으로 변환한다.
2. **예측 보조:** ML 모델이 다음날 상승 확률을 예측해 시그널 필터로 사용한다.
3. **백테스트:** 지정 기간·유니버스로 백테스트를 돌려 성과를 계산한다.
4. **리포트:** 성과 지표 + 자산곡선 차트가 담긴 HTML/Markdown 리포트를 받는다.
5. **반복:** 파라미터를 바꿔 재실행하고, 실험 결과를 폴더에 누적·비교한다.

## 4. MVP 범위 (Scope)

| 구분 | 포함 | 제외 |
|------|------|------|
| 시장 | KRX (코스피/코스닥) | 해외/코인/파생 |
| 데이터 | pykrx, FinanceDataReader (일봉 중심) | 실시간 틱, 호가 |
| AI | LLM 전략 생성, ML 예측 모델 | 강화학습, 자동 튜닝(추후) |

| 인터페이스 | CLI + 리포트 파일(HTML/MD) | 웹 대시보드 |

## 5. 기능 요구사항 (Functional Requirements)

### F1. 데이터 계층 (Data Layer)
- F1.1 pykrx/FinanceDataReader로 일봉(OHLCV), 시가총액, 종목 리스트 수집
- F1.2 로컬 캐시(Parquet/SQLite)로 반복 조회 시 API 재호출 최소화
- F1.3 데이터 소스 추상화 인터페이스(`DataSource`) — 추후 증권사 API 교체 가능
- F1.4 유니버스 정의 (예: 코스피200, 시총 상위 N, 사용자 지정 종목군)

### F2. LLM 전략 생성 (Strategy Generation)
- F2.1 자연어 프롬프트 → 표준 전략 인터페이스(`Strategy`)를 따르는 코드/설정 생성
- F2.2 생성 결과 검증(문법·인터페이스 준수·금지 연산 차단) 후 등록
- F2.3 전략을 버전 관리 가능한 파일로 저장 (재현성)

### F3. ML 예측 모델 (Prediction)
- F3.1 피처 엔지니어링 (기술적 지표, 수익률, 변동성 등)
- F3.2 학습/검증 분리 시 **시간 순서 보존** (leakage 방지, walk-forward)
- F3.3 예측 출력(상승확률/기대수익)을 전략 시그널로 주입 가능
- F3.4 모델 저장/로드, 실험 메타데이터 기록

### F4. 백테스트 엔진 (Backtest)
- F4.1 이벤트/벡터 기반 백테스트 (일봉 기준)
- F4.2 수수료·세금·슬리피지 반영, 체결 가정 명시
- F4.3 look-ahead bias 방지 (t 시점 시그널 → t+1 체결)
- F4.4 포지션 사이징 / 리밸런싱 규칙 설정
- F4.5 결과: 자산곡선, 체결 로그, 포지션 이력 산출

### F5. 성과 분석 & 리포트 (Reporting)
- F5.1 지표: 누적수익률, CAGR, MDD, Sharpe, Sortino, 승률, 회전율
- F5.2 벤치마크 대비 (코스피/코스닥 지수)
- F5.3 자산곡선·드로다운 차트
- F5.4 HTML 또는 Markdown 리포트로 저장 (실험별 폴더)
- F5.5 (선택) LLM이 리포트 요약·해석 코멘트 생성

### F6. CLI & 실험 관리
- F6.1 `quantlab run --strategy ... --universe ... --from ... --to ...` 형태 실행
- F6.2 실험 설정을 config(YAML) 파일로 관리
- F6.3 실험 결과를 타임스탬프 폴더에 저장, 재현 가능한 seed 기록

## 6. 시스템 아키텍처 (개념도)

```
          ┌────────────────────────────────────────────────┐
          │                   CLI (quantlab)               │
          └───────────────┬────────────────────────────────┘
                          │
     ┌────────────┬───────┴────────┬───────────────┬─────────────┐
     ▼            ▼                ▼               ▼             ▼
┌─────────┐  ┌──────────┐   ┌────────────┐  ┌───────────┐  ┌──────────┐
│  Data   │  │   LLM    │   │    ML      │  │ Backtest  │  │ Report   │
│ Source  │  │ Strategy │   │ Predictor  │  │  Engine   │  │ Generator│
│ (pykrx) │  │  Gen     │   │            │  │           │  │          │
└────┬────┘  └────┬─────┘   └─────┬──────┘  └─────┬─────┘  └────┬─────┘
     │            │               │               │            │
     └──── 캐시 ──┴──── Strategy ─┴──── Signal ───┴── Result ──┘
        (Parquet)      Registry
```

- **핵심 원칙:** 각 계층은 인터페이스로 분리 → 데이터 소스, LLM, 모델을 갈아끼울 수 있음
  (제품화 시 증권사 API / 웹 UI 교체 대비)

## 7. 기술 스택 (제안)

| 영역 | 후보 | 비고 |
|------|------|------|
| 언어 | Python 3.11+ | 퀀트 생태계 표준 |
| 데이터 | pykrx, FinanceDataReader | 무료·설치 즉시 사용 |
| 저장 | Parquet + SQLite | 로컬 캐시 |
| ML | scikit-learn (+ 추후 LightGBM/XGBoost) | 가벼운 시작 |
| LLM | Claude API (Anthropic) | 전략 생성/리포트 요약 |
| 백테스트 | 자체 경량 엔진 (또는 vectorbt/backtrader 검토) | MVP는 자체 구현 검토 |
| 리포트 | Jinja2 + Plotly/Matplotlib → HTML | 정적 파일 출력 |
| CLI | Typer / argparse | |
| 설정 | YAML (pydantic 검증) | |

> LLM 연동 세부(모델 선택·프롬프트·비용)는 별도 설계 문서로 분리 예정.

## 8. 로드맵 (Milestones)

- **M0 — 기반 셋업:** 레포 구조, 의존성, 데이터 소스 추상화 + pykrx 연동, 캐시
- **M1 — 백테스트 코어:** 전략 인터페이스, 백테스트 엔진, 성과 지표, 기본 리포트
- **M2 — LLM 전략 생성:** 자연어 → 전략 변환, 검증, 등록 파이프라인
- **M3 — ML 예측:** 피처·학습·walk-forward 검증, 시그널 주입
- **M4 — 리포트 고도화:** 차트/벤치마크/LLM 해설, 실험 비교
- **(추후) M5+ — 제품화:** 페이퍼트레이딩 → 실거래, 웹 대시보드, 멀티유저

## 9. 성공 지표 (Success Metrics)

- 자연어 아이디어 1건 → 백테스트 리포트까지 **10분 이내** 도달
- 동일 설정 재실행 시 **결과 100% 재현**
- 백테스트에 수수료/슬리피지/look-ahead 방지가 **기본 적용**
- 실험 결과가 폴더 단위로 축적되어 **과거 실험 비교 가능**

## 10. 리스크 & 가정

| 리스크 | 대응 |
|--------|------|
| 데이터 편향/생존편향 | 상장폐지 종목 처리 방안 명시, 데이터 한계 문서화 |
| Look-ahead / 데이터 누수 | 시간순 분리 강제, 리뷰 체크리스트 |
| LLM 생성 코드 신뢰성 | 인터페이스 검증 + 샌드박스, 금지 연산 차단 |
| 과최적화(overfitting) | walk-forward, out-of-sample 필수화 |
| 무료 데이터 API 제한/변경 | 데이터 소스 추상화로 교체 용이하게 |
