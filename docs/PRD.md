## 0. 설계 철학 (Design Principles)

이 프로젝트의 최대 리스크는 버그가 아니라 **자기기만(self-deception)**이다. LLM으로 전략을
양산하는 순간, 이것은 백테스트 도구가 아니라 **다중검정(multiple testing)을 통제하는
연구 시스템**이 된다. 아래 원칙은 기능 요구사항보다 상위에 있다.

1. **규율은 통제가 아니다 — 구조로 강제한다.** 혼자 지키기로 한 규칙은 지켜지지 않는다.
   holdout 잠금, 시도 로깅, look-ahead 방지는 "노력"이 아니라 코드가 강제하는 불변식이어야 한다.
2. **미래참조(look-ahead)는 리뷰가 아니라 설계로 막는다.** 연산자 레벨에서 미래를 볼 수 없게
   만들면, 실수해도 미래참조가 불가능하다.
3. **net-of-cost가 기본이다.** 모든 성과의 주 곡선은 비용 반영 후. gross는 opt-in.
4. **모든 전략은 무작위 대조군을 이겨야 존재할 자격이 있다.** 벤치마크만으로는 부족하다.
5. **재현성 = 산출물·데이터·엔진·seed를 함께 잠그는 것.** 프롬프트 재실행이 아니다.

## 1. 개요 (Overview)

**AI Quant Lab**은 국내 주식(KRX)을 대상으로, LLM과 머신러닝을 활용해 퀀트 투자 전략을
**생성 → 백테스트 → 성과 분석**하는 개인용 연구 실험실이다.

전략 아이디어를 자연어로 던지면 LLM이 **검증된 팩터 DSL**로 변환하고, ML 예측 모델이
횡단면 시그널을 보조하며, 백테스트 엔진이 과거 데이터로 성과를 검증한 뒤 리포트로 정리한다.
모든 실험은 자동 로깅되어 다중검정 보정의 근거가 된다.

초기에는 **본인 연구용 도구**로 출발하지만, 추후 **외부 사용자 대상 제품화**가 가능하도록
모듈을 느슨하게 결합하고 각 계층을 교체 가능하게 설계한다.

## 2. 목표 / 비목표

### 2.1 목표 (Goals)
- 자연어 전략 아이디어 → 미래참조가 구조적으로 불가능한 팩터 표현식으로 변환 (LLM)
- ML 모델로 횡단면 순위(rank) 시그널 생성
- 재현 가능하고 신뢰할 수 있는 백테스트 (look-ahead 방지, 비용·슬리피지 반영)
- **다중검정 보정이 내장된** 표준 성과 리포트 (DSR, 셔플 대조군 포함)
- CLI 한 줄로 실험을 반복 실행하고, 실패 포함 모든 실행을 자동 축적

### 2.2 비목표 (Non-Goals, MVP 기준)
- 실시간 시세 연동 / 실거래 자동매매 → **범위 밖 (추후 단계)**
- 페이퍼 트레이딩 → 범위 밖 (추후)
- 웹 대시보드 UI → 범위 밖 (CLI + 리포트 파일로 시작)
- 해외 주식 / 암호화폐 / 파생 → 범위 밖 (KRX 우선)
- 멀티유저 / 인증 / 과금 → 범위 밖 (제품화 단계에서)
- 강화학습 / 자동 하이퍼파라미터 튜닝 → 범위 밖 (다중검정 위험 가중)

## 3. 사용자 & 시나리오

### 3.1 페르소나
- **1차 사용자 (지금):** 전략을 직접 연구하는 개인 (= 나). 파이썬/CLI에 익숙.
- **2차 사용자 (추후):** 코드를 깊게 모르지만 전략을 실험하고 싶은 트레이더.

### 3.2 핵심 사용자 시나리오
1. **아이디어 → 전략:** "거래량 급증 + 최근 20일 약세 종목" 을 자연어로 입력하면
   LLM이 팩터 DSL 표현식으로 변환한다.
2. **예측 보조:** ML 모델이 유니버스 내 forward 수익률의 횡단면 순위를 예측해 시그널로 쓴다.
3. **백테스트:** 시점정합(point-in-time) 유니버스로 백테스트를 돌려 net 성과를 계산한다.
4. **무결성 검증:** DSR·셔플 대조군·벤치마크 대비가 리포트에 자동 포함된다.
5. **리포트:** 성과 지표 + 자산곡선 + 무결성 진단이 담긴 HTML/Markdown 리포트를 받는다.
6. **반복:** 파라미터를 바꿔 재실행하고, 모든 실행(실패 포함)이 시도 카운트에 누적된다.

## 5. 기능 요구사항 (Functional Requirements)

### F1. 데이터 계층 (Data Layer)
- F1.1 pykrx/FinanceDataReader로 일봉(OHLCV), 시가총액, 종목 리스트 수집
- F1.2 로컬 캐시(Parquet/SQLite) — **원본 OHLCV + 조정계수 분리 저장**, 읽는 시점 조정
- F1.3 데이터 소스 추상화 인터페이스(`DataSource`) — 추후 증권사 API 교체 가능
- F1.4 데이터 스냅샷마다 **스냅샷 ID(해시)** 부여 → 재현성 번들의 구성요소

### F1-DQ. 데이터 정합성 스펙 (Data Integrity Spec) — **신설**
백테스트가 깨지는 곳은 엔진이 아니라 여기다. 별도 명세로 고정한다.
- **DQ.1 수정주가:** 조정 방식을 **하나로 고정**(pykrx `adjusted` vs FDR 방식이 다름).
  원본 + 조정계수를 저장하고 read-time 조정 → point-in-time 조정 보장, 사후 액면분할 재조정 오류 방지.
- **DQ.2 상장폐지 종목:** 상폐 종목 데이터를 확보해 **생존편향 제거**. 확보 한계는 문서화.
- **DQ.3 종목 필터:** 우선주(접미어 5/7/9/K/L… **+ 종목명 '우'/'우B'** 병행), 스팩(종목명 '스팩'),
  리츠, ETF/ETN(별도 티커리스트 차집합) 제외.
- **DQ.4 코퍼레이트 액션:** 액면분할·유상증자·병합 반영(조정계수로 흡수).
- **DQ.5 거래정지/관리종목:** 해당일 체결 불가. **과거 PIT 상태는 무료 데이터로 확보 곤란 →
  데이터 가용성 리스크로 명시하고 근사치 사용**(리스크 표 참조).
- **DQ.6 가격제한:** 상·하한가 ±30% 도달 시 **불리한 방향 체결 불가** 가정
  (상한가 매수 불가 / 하한가 매도 불가).

### F2. LLM 전략 생성 (Strategy Generation) — 팩터 DSL 2층 구조
코드 생성을 피하는 결정적 이유는 안전성이 아니라 **look-ahead bias**다. DSL의 시계열 연산자를
전부 "과거만 본다"로 구현하면 미래참조가 **설계상 불가능**해진다.
- F2.1 LLM 출력 형식: `alpha`(팩터 표현식) + `universe` + `portfolio`(config)의 YAML 2층 구조
  ```yaml
  alpha: "rank(ts_mean(volume, 5) / ts_mean(volume, 20)) * rank(-ts_delta(close, 20))"
  universe: {market: [KOSPI, KOSDAQ], top_mktcap: 300, min_turnover: 5e8}
  portfolio: {n_positions: 20, weighting: equal, rebalance: weekly}
  ```
- F2.2 연산자 ~30개(WorldQuant Alpha 표현식 계열): `ts_mean/ts_std/ts_rank/ts_delta/...`(후방 시계열),
  `rank/scale/...`(시점 t 횡단면).
- F2.3 파서는 **화이트리스트 AST 인터프리터** — 허용 목록만 파싱(블랙리스트는 우회당함).
- F2.4 **시간 전체축을 건드리는 연산자 금지**(전구간 z-score, `center=True` 등) — 크로스섹션(시점 t)
  또는 후방 시계열만 허용.
- F2.5 산출물(YAML)을 **해시로 고정**해 버전 관리 → 재현성의 단위.
- F2.6 표현력 한계 도달 시에만 3단계(사람 리뷰 후 커밋하는 코드)를 연다. 처음부터 열지 않는다.

### F3. ML 예측 모델 (Prediction) — 횡단면 랭크 회귀
- F3.1 타깃: 유니버스 내 **forward N일 수익률의 횡단면 순위를 [-0.5, 0.5]로 정규화 → 회귀**.
  (이진 분류 금지: 시장 베타가 정답 지배, 크기 정보 소실, 필요한 건 절대예측이 아닌 상대순위.)
- F3.2 horizon = **5~20일**(일간 회전은 비용에 잠식됨, §7 비용 참조).
- F3.3 피처: **F2와 동일한 누수불가 프리미티브 라이브러리 재사용**(단일 진실 공급원).
- F3.4 검증: walk-forward + **학습·검증 사이 forward horizon 만큼 embargo gap**(라벨 겹침 누수 방지).
- F3.5 평가지표: **일별 Rank IC, IC IR, 상위-하위 분위 스프레드**(accuracy/AUC 금지).
- F3.6 모델: **LightGBM**(2코어/8GB 적합, 이 태스크에 scikit-learn 단독보다 우수).
- F3.7 모델 저장/로드 + 실험 메타데이터 기록.

### F4. 백테스트 엔진 (Backtest) — 목표비중 행렬 추상화
- F4.1 인터페이스: **전략 `(날짜, 데이터) → 목표비중 Series` / 엔진 `목표비중 DataFrame →
  체결·비용·자산곡선·포지션 이력`**. 일봉 롱온리 리밸런싱, 벡터화(numpy).
- F4.2 비용: 수수료 + **매도세(코스피 0.05%+농특세 0.15%, 코스닥 0.20% — 양쪽 총 0.20%, 2026 기준)**
  + 슬리피지. 왕복 ≈ 0.25% 가정.
- F4.3 look-ahead 방지: t 시점 시그널 → **t+1 체결** 강제.
- F4.4 포지션 사이징 / 리밸런싱 규칙 설정.
- F4.5 결과: 자산곡선, 체결 로그, 포지션 이력, **회전율·비용 drag**.
- F4.6 **net-of-cost가 주 곡선**, gross는 opt-in.
- **F4.7 엔진 검증(2층, M1 완료조건):**
  - (a) **골든값 단위 테스트** — 3종목×5일 손계산 포트폴리오와 **정확히 일치**
    (t+1·비용·비중 로직 버그 검출).
  - (b) **지수 추종 오차 테스트** — 재구성 가능한 유니버스로 broad index를 **허용오차 내 추종**
    (데이터·수정주가 버그 검출). *KOSPI200은 PIT 구성종목 부재로 정확 복제 불가 → 벤치마크로만 사용.*

### F5. 성과 분석 & 리포트 (Reporting)
- F5.1 지표: 누적수익률, CAGR, MDD, Sharpe, Sortino, 승률, **회전율, 비용 drag**
- F5.2 벤치마크 대비 (코스피/코스닥 지수)
- F5.3 **다중검정 진단(F7)을 리포트 기본 항목으로**: DSR, 셔플 대조군 p-value
- F5.4 자산곡선·드로다운 차트
- F5.5 HTML 또는 Markdown 리포트로 저장 (실험별 폴더)
- F5.6 (선택) LLM이 리포트 요약·해석 코멘트 생성

### F6. CLI & 실험 관리
- F6.1 `quantlab run --strategy ... --universe ... --from ... --to ...` 형태 실행
- F6.2 실험 설정을 config(YAML)로 관리
- F6.3 **재현성 번들**: 결과에 `hash(전략 산출물 + 데이터 스냅샷 ID + 엔진 git SHA + seed)` 기록.
  재현 = 이 4개를 함께 잠그고 재실행하는 것(프롬프트 재실행 아님).

### F7. 연구 무결성 인프라 (Research Integrity) — **신설·최상위 중요**
다중검정과 자기기만을 코드가 강제로 막는 계층. **규율이 아니라 구조.**
- **F7.1 자동 시도 로깅:** 모든 백테스트 실행을 감싸는 컨텍스트매니저/데코레이터로
  **실패 포함 전 실행을 자동 기록**(끄는 옵션 없음). 시도 카운트가 틀리면 DSR이 무의미해진다.
- **F7.2 Deflated Sharpe Ratio(DSR):** 성과 리포트 기본 항목. **유효 N**은 순진한 시도 수가 아니라
  **시그널 상관행렬로 클러스터링한 클러스터 수**(상관된 변형의 과잉 페널티 방지).
- **F7.3 PBO(Probability of Backtest Overfitting):** CPCV 기반으로 병기. DSR("이 Sharpe가 우연인가")과
  PBO("선택 절차가 과적합되는가")는 다른 질문.
- **F7.4 셔플 대조군:** 시그널을 매일 횡단면 셔플 → **N=100회 귀무분포** 생성 →
  실제 전략 지표의 **경험적 p-value**. **p ≥ 0.05면 자동 폐기.**
- **F7.5 Holdout 잠금(구조적 강제):** 최종 검증용 holdout 기간은 **일반 파이프라인에서 로드 불가**.
  별도 명령으로만 열리고, 그 명령은 **감사로그에 append**(전략 해시·시각·접근 횟수). 재접근 시 경고.

## 6. 시스템 아키텍처 (개념도)

핵심은 **누수불가 프리미티브 라이브러리**가 코어이고, DSL과 ML이 그 위의 두 소비자라는 점이다.

```
          ┌────────────────────────────────────────────────┐
          │                   CLI (quantlab)               │
          └───────────────┬────────────────────────────────┘
                          │
   ┌───────────┬──────────┴─────────┬──────────────┬──────────────┐
   ▼           ▼                    ▼              ▼              ▼
┌───────┐  ┌────────────────────────────┐   ┌──────────┐  ┌──────────┐
│ Data  │  │  누수불가 프리미티브 코어  │   │ Backtest │  │ Report + │
│Source │─▶│  (point-in-time ts/CS ops) │──▶│  Engine  │─▶│ 무결성   │
│(pykrx)│  │   ├── F2: DSL 파서/해석기   │   │(목표비중)│  │ (F7)     │
└───────┘  │   └── F3: ML 피처/LightGBM  │   └──────────┘  └──────────┘
  캐시     └────────────────────────────┘        │
(원본+계수)      (단일 진실 공급원)          자동 시도 로깅(F7.1)
```

- **의존구조:** M1이 프리미티브 + 엔진 + 검증을 낳고, **M2(DSL)·M3(ML)은 그 코어의 두 소비자**.
  일렬(M1→M2→M3)이 아니다.
- 각 계층은 인터페이스로 분리 → 데이터 소스·LLM·모델 교체 가능(제품화 대비).

## 7. 기술 스택 (제안)

| 영역 | 후보 | 비고 |
|------|------|------|
| 언어 | Python 3.11+ | 퀀트 생태계 표준 |
| 데이터 | pykrx, FinanceDataReader | 무료·설치 즉시 사용 |
| 저장 | Parquet + SQLite | 원본+조정계수 분리 캐시 |
| ML | LightGBM | 횡단면 랭크 태스크 적합, 2코어/8GB OK |
| LLM | Claude API (Anthropic) | 전략(DSL) 생성/리포트 요약 |
| 백테스트 | **자체 목표비중 행렬 엔진(300~500줄)** | 재현성·비용·t+1 100% 통제. bt는 참고만 |
| 무결성 | DSR/PBO/셔플 자체 구현 | Bailey & López de Prado |
| 리포트 | Jinja2 + Plotly/Matplotlib → HTML | 정적 파일 출력 |
| CLI | Typer / argparse | |
| 설정 | YAML (pydantic 검증) | |

**백테스트 라이브러리를 안 쓰는 이유:** backtrader(유지보수 정체·이벤트루프라 2000종목×10년 느림,
2코어에서 반복 사이클 붕괴), vectorbt(파라미터 스윕이 3D 배열로 커져 8GB에서 터짐·횡단면 전략 표현 어색).
목표비중 행렬은 T×N ≈ 2500일×300종목×8B ≈ 6MB로 메모리 문제 없음.

**비용 근거:** 매도세 코스피 0.05%+농특세 0.15% / 코스닥 0.20% (양쪽 총 0.20%, 2026 기준).
왕복 ≈ 0.25%. 일간 회전 시 연 60%+ 비용 → 알파가 이기기 불가 → horizon 5~20일.

## 8. 로드맵 (Milestones)

- **M0 — 기반 셋업:** 레포 구조, 의존성, `DataSource` 추상화 + pykrx 연동, 원본+조정계수 캐시,
  데이터 정합성 스펙(F1-DQ) 구현.
- **M1 — 코어 + 백테스트 + 무결성:**
  - 누수불가 프리미티브 라이브러리(코어)
  - 목표비중 행렬 엔진 + **엔진 검증 2층(F4.7 (a)+(b)) 통과 = 완료조건**
  - 성과 지표, 기본 리포트
  - 연구 무결성 인프라(F7): 자동 시도 로깅, DSR, 셔플 대조군, holdout 잠금
  - **손으로 전략 5~10개 작성** → 공통 어휘 도출(DSL 연산자 세트의 근거)
- **M2 — LLM 전략 생성:** M1에서 굳힌 어휘로 DSL 파서(화이트리스트 AST) + LLM 연동 + 검증.
- **M3 — ML 예측:** 프리미티브 재사용 피처 + LightGBM + walk-forward(embargo) + Rank IC 평가 + 시그널 주입.
- **M4 — 리포트 고도화:** 차트/벤치마크/LLM 해설, 실험 비교, PBO 대시.
- **(추후) M5+ — 제품화:** 페이퍼트레이딩 → 실거래, 웹 대시보드, 멀티유저.

> **순서 근거:** DSL 연산자 세트는 팩터를 직접 몇 개 만들어봐야 필요 어휘를 안다. M1에서 손으로
> 짜본 뒤 공통 어휘를 DSL로 굳히고(M2), 같은 프리미티브 위에 ML을 얹는다(M3). M2·M3은 형제 관계.

## 9. 성공 지표 (Success Metrics)

**엔지니어링:**
- 자연어 아이디어 1건 → 백테스트 리포트까지 **10분 이내**
- 재현성 번들(산출물+데이터+엔진+seed) 재실행 시 **결과 100% 재현**
- 백테스트에 비용/슬리피지/t+1이 **기본 적용**

**연구 무결성 (자기기만 방지):**
- 모든 실험이 **벤치마크 대비 + 셔플 대조군 대비**로 리포트됨. **셔플을 못 이기면(p≥0.05) 자동 폐기**
- 성과 리포트에 **DSR·PBO 기본 표시**, 시도 카운트가 실패 포함 자동 집계됨
- Holdout 접근이 **감사로그로 추적**됨(전략당 접근 횟수 가시화)

## 11. 기본 유니버스 정의 (Point-in-Time)

코스피200을 기본값으로 두면 생존편향 + look-ahead가 동시에 들어간다(과거 편입이력은 무료로
확보 곤란 — 개인 퀀트 백테스트가 조용히 망하는 1순위 원인). 대신 **매 리밸런스일 t마다 재구성**:

1. `stock.get_market_ticker_list(t)` — 그날 실제 상장돼 있던 종목(pykrx 지원이 핵심)
2. 제외: 우선주(접미어 + 종목명), 스팩, 리츠, ETF/ETN, 관리종목, 거래정지
3. 시총 상위 N (**기본값 300**)
4. 유동성 필터: **20일 중앙값 거래대금 ≥ 5억**(슬리피지 가정 성립 범위)

→ 편입 이력 데이터 없이도 **시점정합이 구조적으로 보장**된다.
